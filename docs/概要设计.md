# AI 文档知识库概要设计

状态：持续维护中的设计；初稿 2026-11-02，更新 2026-11-04。已实现情况以代码为准，未实现的能力为设计目标。

## 1. 项目目标

面向个人学习与简历展示，提供一个以文档为依据的知识库。用户可以组织资料、查找文档，并在后续阶段基于知识库提问、查看回答所依据的来源。项目同时用于学习 Vue 3、NestJS、数据库及 RAG 工程实践。

成功标准：用户能够登录、创建知识库、上传并查看文档；AI 阶段能够从指定知识库中找到相关片段，生成回答并展示可核对的来源。无法找到依据时应明确说明，不能把生成内容标作事实来源。

## 2. 范围与阶段

| 能力 | 第一阶段：基础知识库 | 后续：AI 知识库 |
| --- | --- | --- |
| 用户 | 注册、登录、退出及数据隔离 | 按需扩展账号安全能力 |
| 知识库 | 创建、列表、详情、修改、删除 | 团队协作和权限暂不纳入 |
| 文档 | PDF、MD、DOC、DOCX 上传、列表、下载、删除；PDF/MD 基础预览 | Word 转换预览、解析结果与片段查看 |
| 搜索 | 当前知识库和全局范围的文件名搜索 | 正文关键词、语义检索与融合 |
| AI 问答 | 入口展示开发中，不生成虚假回答 | 指定知识库问答、流式输出、引用及历史会话 |
| 解析 | 不执行，上传后显示「已上传」 | 解析、切分、向量化、重试和进度 |

第一阶段先支持可复制文字的 PDF 的浏览器预览；PDF 预览能力受浏览器影响。MD 渲染前必须清理不安全 HTML。DOC 和 DOCX 首期保证上传和下载，预览及内容解析需要后续转换方案。扫描 PDF OCR、复杂表格识别不作为第一阶段验收条件。

## 2.1 当前实现状态（2026-11-04）

已实现注册、登录、刷新、退出及访问令牌会话校验；知识库创建、列表、详情和修改已有接口及前端接入。注册与登录已由用户验证。知识库删除、文档模型与文件管理、真实 AI 问答仍未实现。前端有 Element Plus 知识库框架及 Axios 请求客户端；文件相关控件仍是占位。更多历史和验证范围见[开发记录](2026-11-02-项目搭建与后端开发记录.md)。

## 3. 总体架构

```text
浏览器：Vue 3 + TypeScript
        │ HTTPS / 本地 HTTP
        ▼
NestJS API ───── PostgreSQL + pgvector
    │                  用户、知识库、文档及后续索引
    ├──────────── 本地文件存储（后续可替换为对象存储）
    ├──────────── 模型 API（后续：Embedding / 对话）
    └──────────── Redis + BullMQ（后续）
                         │
                         ▼
                   Python 文档解析服务（后续）
```

- Vue 负责页面、交互、上传进度和登录状态；不直接连接数据库或持有模型密钥。
- NestJS 负责认证、数据访问控制、知识库与文件管理；后续负责协调解析任务、检索和模型调用。
- PostgreSQL 保存业务数据；pgvector 已在本地数据库启用，第一阶段暂不创建向量表。
- 文件系统保存原文件。应用通过文件存储接口封装路径，不直接暴露物理路径。
- Redis、Python、模型 API 在 AI 阶段接入；解析任务运行方式及内部通信协议在该阶段细化。

## 4. 核心业务流程

### 4.1 文档上传与后续入库

第一阶段：选择知识库 → 校验用户权限和文件 → 保存原文件与文档记录 → 返回「已上传」→ 用户可浏览、下载或删除。

后续：已上传 → 排队 → 解析 → 切分 → 向量化并写入索引 → 可用于问答；任一步失败时记录错误并提供重试。状态表示当前版本处理情况，不能仅因为上传成功就标记为「可问答」。

### 4.2 问答与引用（后续）

选择知识库 → 输入问题 → 在有权限的知识库内检索 → 获取相关文档片段 → 调用对话模型 → 展示回答与引用 → 点击引用打开文档；仅在解析结果有可靠页码时定位页码。检索阶段即限定用户和知识库，不能把无权访问的内容送入模型。

### 4.3 文件名搜索

知识库详情页搜索只筛选当前知识库文件名；顶部全局搜索覆盖当前用户有权访问的知识库文件名。搜索结果显示所属知识库并可进入文档详情；无结果时给出明确提示。第一阶段不承诺全文或语义搜索。

## 5. 数据模型概览

```text
User 1 ── N KnowledgeBase 1 ── N Document
```

第一阶段的字段和约束见《第一阶段详细设计》。后续预计新增处理任务、文档版本或索引批次、文档片段及向量、会话、消息、引用等；它们现在只是候选模型，尚未决定表结构或向量维度。更换 embedding 模型时需要能够识别旧索引并重建。

## 6. 主要设计原则

- 每次访问知识库、文档及原文件都由后端核验归属，前端隐藏入口不能代替权限控制。
- 文件名视为展示数据，存储键由服务端生成；校验类型和大小，避免路径穿越，不能信任客户端声明的 MIME 类型。
- 本地开发数据库账号与密码只用于本机开发。生产部署需要独立密钥、可靠的文件存储与备份。
- 文件与数据库不是同一事务：使用可重试清理机制处理失败，不能只依赖数据库级联删除。
- 调用外部 AI API 前应明确文档内容会发送给所选服务商；密钥只存服务端配置。
- 第一阶段以可运行闭环为目标，架构保持可扩展，不提前引入所有服务。

## 7. 待确认事项

已确定使用邮箱注册，单文件上限 50 MiB，同一用户下知识库名称不可重复；第一阶段支持刷新后保持登录。当前已开放自助注册；实际预览体验仍需确认。向量模型、维度、OCR、AI 服务商及文档格式解析质量应在 AI 阶段基于真实样本确定。
